# AetherMind · GPU Node

Мобильный Telegram Mini App для каталога GPU-конфигураций, заявок на аренду и поддержки. Первая поставка — **приём заявок без оплаты**, не запущенная сеть GPU и не инвестиционная программа.

## Что работает

- Welcome, дашборд, каталог, кластер, кошелёк; мобильная адаптация от 320 px.
- Telegram initData HMAC-проверка, срок входных данных 5 минут, серверная сессия 6 часов в памяти вкладки.
- Аккаунты PostgreSQL, заявки с профилями Eco/Balanced/Performance, защита от повторной отправки и одной открытой заявки на пользователя.
- Поддержка: обращение, ответ владельца, просмотр в аккаунте.
- Панель владельца по OWNER_TELEGRAM_ID: список заявок, изменение статуса, ответы, журнал действий.
- Приглашения через /start r_ID без денежных бонусов; самореферал запрещён.
- Проверка реальной доступности БД в health. Неизвестная загрузка сети показана как «нет данных».
- Четыре AI-generated изображения, WebP, матрица PNG-иконок 48/72/96/120/144/180/192/512/1024, SVG-навигация и PNG 24/48/72.
- CountUp только для отображения серверного баланса; Lottie light splash; CSS shimmer, desktop tilt, Telegram haptic, reduced-motion. Наклон на телефоне отключён ради прокрутки и производительности.

## Не подключено — важно

- Выделение GPU, контейнеров, SSH/Jupyter; реальные мощности/цены/загрузка/модели не подделываются.
- Приём и вывод средств, QR, платежные WebSocket-события, реферальные выплаты. `/api/payments` и `/api/withdrawals` возвращают 503 и не изменяют баланс.
- Прямой доступ к GPU не появляется от установки приложения на VPS. VPS с 1 ГБ RAM обслуживает интерфейс/API, не вычисления.
- Quantum AI Server — маркированная художественная концепция, не товар.
- На старте нет гарантированной доходности, статуса «99.8% Load», фиктивных начислений или задержек «смарт-контракта».

## Почему не включена криптооплата

Продажа цифровых услуг внутри Telegram должна использовать Stars. GPU-доступ в этом проекте рассматривается как цифровая услуга. NOWPayments/Cryptomus, USDT TRC20/BEP20, BTC и TON из исходного ТЗ не включены до согласования допустимой архитектуры. Запуск оплаты требует отдельного решения владельца и интеграционных испытаний. Нельзя считать одно подтверждение универсальным критерием финальности для всех сетей; нельзя имитировать смарт-контракт.

## Стек

React 18, TypeScript, Vite 7; NestJS 11 + Fastify; Prisma 7 + PostgreSQL; Node 22; Nginx + systemd. npm workspaces, lockfile. Redis/BullMQ не нужны для текущих заявок; добавляются при появлении реальных задач. Tailwind не требуется: дизайн-система описана CSS-переменными и компонентами. Шрифты Inter/Space Grotesk обслуживаются локально, без запросов к Google Fonts.

## Установка

1. В обычном Termux запустить 01_gpunode_create.sh. Он создаёт ~/gpunode, коммит, публичный joxydev/gpunode и push main. Существующий чужой каталог/репозиторий не перезаписывает. Токен бота здесь не нужен.
2. Там же запустить 02_gpunode_vps.sh. Он скачивает точный main SHA с GitHub, передаёт его по SSH и собирает на Ubuntu 24.04 x64. Ключ ~/.ssh/joxy_senko, сервер joxy@31.77.226.26. На VPS вводятся токен, ID владельца, email. Порты 80/443 должны быть открыты в панели хостера.

При повторном деплое используются сохранённые настройки gpunode. Старые таблицы GPU Marketplace не читаются и не удаляются. Известный прежний IP-vhost временно заменяется, его конфигурация сохраняется. При неуспехе проверки запуска возвращается прежний сайт; миграции БД автоматически не откатываются. Если бот имеет другой webhook, настройка бота останавливается без его перезаписи.

Доступ: https://31.77.226.26/; HTTP перенаправляется на HTTPS. Сертификат IP shortlived, обновление каждые 6 часов. Имя сертификата gpu-marketplace-ip оставлено для сохранения существующей цепочки обновления.

## Эксплуатация

```bash
sudo systemctl status gpunode --no-pager
sudo journalctl -u gpunode -n 60 --no-pager
sudo systemctl list-timers gpu-cert-renew.timer --no-pager
curl --fail https://31.77.226.26/api/health
```

Не присылайте runtime.env в чат. Настройки: /srv/apps/gpunode/shared/runtime.env; релизы: /srv/releases/gpunode; копии перед деплоем: /srv/backups/gpunode. Автоматическая ежедневная копия на другой сервер ещё не настроена; перед приёмом денег она обязательна. Старые релизы автоматически не удаляются — следите за df -h /.

Кнопка меню и /start настраиваются API. Если нужна ещё и кнопка запуска в профиле бота: BotFather → /mybots → Bot Settings → Configure Mini App; этот пункт не заменяется установкой меню.

## Локальная разработка / CI

```bash
npm ci --ignore-scripts
npm run db:generate
npm test
npm run build
```

Нужны Node 22 и PostgreSQL для API; деплой собирает на VPS. CI имеет отдельную временную PostgreSQL для интеграционных проверок, не подключается к VPS. Не запускайте integration.mjs против рабочей БД: он создаёт тестовые аккаунты/заявки.

## Следующие этапы

1. Выбрать модель бизнеса: аренда GPU для собственных задач клиента или доход владельца от сдачи его GPU. Это разные договоры, учёт и API.
2. Выбрать и подключить провайдера либо GPU-agent для собственных физических серверов, подтвердить наличие и цены.
3. Реализовать Provisioning → Ready → Running → Stopping → Terminated, идемпотентные задания, таймауты, повторы и изоляцию клиентов; управление SSH-ключами, Jupyter credentials.
4. Реальная телеметрия с проверкой свежести, приватность имён/данных моделей клиентов, учёт потребления.
5. Согласовать платежную схему, реализовать ledger с резервированием, подписанные webhooks, сверку сумм и валют, идемпотентность, возвраты и реальные статусы.
6. Расширить админ-панель ролями/аудитом, offsite-backup, восстановление из копий, мониторинг сертификата и диска, нагрузочные и security-тесты.
