# Панель владельца и тикеты

## Доступ

Вкладка `Управление` появляется только у Telegram ID из `OWNER_TELEGRAM_ID`. Каждый маршрут `/api/admin/*` повторно проверяет серверную сессию, пользовательское соглашение, актуальную оферту и совпадение ID владельца. Скрытие вкладки во frontend не используется как средство авторизации.

## Пользователи

- `GET /api/admin/users` — постраничный список и безопасный поиск по имени, username или Telegram ID.
- `GET /api/admin/users/:id` — регистрация, текущий ledger-баланс, сумма только подтверждённых положительных депозитов, выбранный тариф, документы, заявки, оборудование, тикеты и прямые приглашённые.
- В сумму депозитов входят только виды `DEPOSIT`, `DEPOSIT_CONFIRMED` и `CRYPTO_DEPOSIT_CONFIRMED`. Произвольные кредиты и расчётная доходность не выдаются за вложенные средства.
- Обычный пользователь видит приглашённых анонимно; реальные Telegram ID доступны только владельцу.

## Заявки оборудования

Поле `RentalRequest.paymentStatus` имеет только два состояния: `WAITING` и `PAID`. Добавочная миграция присваивает всем существующим и новым заявкам `WAITING`. В этом релизе нет API ручного подтверждения оплаты: `PAID` должен в будущем устанавливаться только после проверенного webhook платёжного провайдера.

Оператор может перевести заявку в работу или закрыть её с решением `ACCEPTED / REJECTED` и обязательной причиной для пользователя. Закрытая заявка не открывается повторно текущим API.

## Поддержка

`ticket_messages` хранит неизменяемую последовательность сообщений `USER / OWNER`. При миграции исходные `Ticket.message` и `Ticket.reply` сохраняются и копируются в историю. Поля `ownerUnread` и `userUnread` дают счётчики в интерфейсе без чтения содержимого на клиенте.

Цикл тикета:

1. Пользователь создаёт вопрос или жалобу — оператор получает непрочитанный тикет.
2. Оператор открывает диалог, переводит его в работу или отвечает.
3. Ответ создаёт уведомление в аккаунте пользователя.
4. Пользователь может отправлять уточнения; тикет снова становится новым для оператора.
5. После ответа оператор закрывает тикет. Новые сообщения в закрытый тикет сервер отклоняет; при необходимости оператор может открыть его повторно.

Ограничения: 5 новых тикетов на пользователя в час, 20 пользовательских сообщений в один тикет в час, 2–2000 символов для последующих сообщений и максимум 200 сообщений в выдаваемой истории.

## Финансовая граница

Панель только читает ledger и показывает статусы. Она не создаёт депозит, не меняет баланс, не запускает Epoch и не начисляет доход. Платёжные маршруты остаются закрытыми до отдельной интеграции с подтверждением блокчейна/провайдера.
