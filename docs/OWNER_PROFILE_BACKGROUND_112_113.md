# Профиль пользователя владельца и фон — 112/113

## Задача и план

Исправить HTTP 500 при повторном выборе ранее пополненного пользователя в управлении владельца и исчезновение фонового изображения при прокрутке. Работать от актуального main `b236706d4e5a6afe927e76ad6048e32e12c18772`, сохраняя уже выпущенные GPU-изображения, LED-эффекты, текущую оферту, TON и финансовые операции. Проверить повторное начисление через настоящий API на отдельной базе и интерфейс на разных экранах. Передать следующие свободные файлы 112/113 по действующему порядку GitHub → VPS.

1. Воспроизвести сбой и определить, падает ли операция начисления или чтение профиля.
2. Исправить JSON-представление заказов и отображение даты неактивированного договора.
3. Закрепить статичный фон в пределах viewport без обработчиков прокрутки и новых анимаций.
4. Проверить суммы, повтор запросов, права владельца, старые договоры, локализации, прокрутку и модальные окна.
5. Подготовить полный выпуск с контрольными суммами, тестами и существующим резервным копированием.

## Причины и изменения

`GET /admin/users/:id` возвращал `UserLease` напрямую из Prisma. После появления GPU-заказа в ответ попадали BigInt-поля, включая нулевые `baseAccruedMicros` и `compoundProfitMicros`. Fastify падал с `Do not know how to serialize a BigInt`. Поэтому пользователь без оборудования открывался, а тот же пользователь после заказа переставал открываться для следующего пополнения. Исторические договоры также содержат эти поля.

Обработчик теперь использует существующий `presentLease`, как `/me` и административный список оборудования. Денежные значения передаются точными десятичными строками; преобразования в Number и глобального изменения BigInt нет. Профиль остаётся чтением: не запускает settlement и не создаёт проводок. Серверная проверка владельца, журнал, блокировки баланса и idempotency начисления сохраняются.

Для `PROVISIONING` срок до активации равен null. Панель владельца теперь показывает локализованное «Ожидает активации» вместо даты 1970 года.

Фон был ограничен 1000 px на мобильном экране и 1150 px на ПК и затем затухал в однотонный цвет. Теперь существующий WebP рисуется неподвижным `body::before` размером с viewport. `cover` сохраняет пропорции; `isolation:isolate` помещает декор над заливкой body и под интерфейсом, `pointer-events:none` пропускает нажатия. Каждая ширина загружает один соответствующий ресурс. Нет `background-attachment:fixed`, растяжения картинки на высоту длинной страницы, новых циклов JavaScript, canvas или анимации фона. Мобильное отключение backdrop-filter сохраняется.

## Проверки

- Production TypeScript/Vite build и 59 backend + 6 frontend unit-тестов.
- Прежний JSON-ответ воспроизведён на отдельной embedded PostgreSQL базе: профиль после покупки возвращает 500 именно из-за BigInt. Исправленный ответ возвращает 200.
- HTTP owner-credit: пополнение → покупка → открытие профиля → отдельное повторное пополнение → повтор запроса с тем же ключом → повторное открытие. Баланс, одна проводка и одна запись истории подтверждены. Проверены активированный договор, исторический договор с null principal и точное значение `9007199254.740993`; обычному пользователю отказ 403, без сессии 401. Чтение профиля не меняет договор и число проводок.
- Основные HTTP, financial, admin-credit, public runtime, GPU Live, bot и network suites на отдельной базе; Telegram transport имитируется.
- 59 браузерных проверок с синтетическими ответами: RU/EN/RO; два независимых пополнения и три открытия пользователя на 390/1440 px; фон на 320/390/768/1440 px и в 844×390; главная, тарифы, native dialog, финансы и партнёры; изменение высоты viewport под клавиатуру. Нет ошибок JavaScript, горизонтального переполнения и новых нативных img.
- Пиксельная проверка фона на пяти размерах: при scrollY 0/1500/3000 фон одинаков; на старой сборке нижняя часть действительно однотонна. Внутренние скриншоты не входят в выдаваемый пакет.
- 10 deploy fixtures, 5 bot configuration fixtures, 6 public runtime fixtures; shell syntax и целостность двух итоговых файлов проверяются отдельно при упаковке.

Браузерный стенд — Chromium headless с программным ANGLE SwiftShader, не физический телефон или Telegram WebView. Точные замеры прокрутки с CPU throttle ×4 передаются в отчёте. Native PostgreSQL отсутствует локально; полный `ops/vps-ci.py`, включая проверку межсессионного advisory lock Epoch worker, остаётся обязательным в VPS-сценарии. Embedded PostgreSQL работает с одной сессией и не подтверждает эту проверку конкуренции процессов.

## Установка и восстановление

В Termux выполнить по порядку:

```bash
bash ~/storage/downloads/112_aethermind_owner_profile_github.sh
bash ~/storage/downloads/113_aethermind_owner_profile_vps.sh
```

112 содержит Git bundle, проверяет контрольную сумму, сохраняет локальные изменения, объединяет совместимые изменения main обычным merge/push и записывает точный SHA для 113. GitHub Actions автоматически не запускаются.

113 развёртывает сохранённый SHA, проверяет новые исправления в архиве, создаёт бэкап `/srv/backups/gpunode/owner-profile-113-<UTC>`, последовательно собирает приложение и выполняет действующий полный CI на одноразовой native PostgreSQL до переключения release. Production smoke использует безопасные чтения. Новых миграций для этого исправления нет; реальные балансы и остатки каталога не пересоздаются.

Существующий аварийный сценарий сохраняет данные и оценивает совместимость перед возвратом к прежнему коду. Базу нельзя восстанавливать поверх новых акцептов, договоров или выплат. При несовместимости применяется исправляющий выпуск, а не возврат финансовых данных из старого dump.

Реальный GitHub, VPS и Telegram Bot API из окружения разработки не изменялись. После успешного 113 полностью закрыть и заново открыть Mini App, повторно выбрать ранее пополненного пользователя и проверить длинную страницу.
