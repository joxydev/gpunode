# Проверка заказа с владельцем

Платёжный провайдер и оборудование пока не подключены. Владелец выдаёт **тестовые USDT** отдельно от реального учётного баланса. Они не выводятся, не начисляют доход и не означают подтверждённый депозит. Все суммы хранятся в целых миллионных долях USDT; предел одного начисления — 1 000 000 USDT.

1. Пользователь принимает соглашение и актуальную оферту, выбирает доступный тариф.
2. Владелец открывает «Управление → Пользователи → пользователь», вводит целую сумму и причину. API требует авторизацию владельца и UUID ключа повтора, фиксирует инициатора и аудит. Повтор с тем же ключом возвращает исходный результат.
3. Пользователь видит тестовый баланс в «Профиль» и «Финансы», выбирает «Проверить и заказать». Сервис проверяет достаточность тестовых средств **на сервере**, резервирует стоимость в отдельном тестовом журнале и сохраняет снимок выбранного тарифа и версии оферты.
4. Владелец видит счётчик заказов и «Управление → Заявки» со статусом «Тестовые средства». Решение с обязательной причиной: «Принять» или «Отказать».
5. Принятие создаёт «Мои активы» в профиле со статусом «Ожидает назначения», без запуска Epoch и без фиктивных показателей GPU. Отказ однократно возвращает тестовые средства. Пользователь получает уведомление при обновлении страницы или очередной проверке аккаунта.

Реальный LedgerEntry, UserLease, баланс, вывод и начисления **не изменяются** тестовыми операциями. Повторные запросы, одновременные заказы и повторные решения защищены блокировками и уникальными ключами. Схема `202609230002_test_cycle` только добавляет данные. На VPS `ops/vps-ci.py` сначала запускает полные HTTP-тесты на временной базе PostgreSQL, затем перед включением релиза создаётся дамп действующей БД.

Для будущего подключения настоящей работы потребуются подтверждённый платёж, резерв слота оборудования, подписанный контракт и телеметрия провайдера. Статус тестового актива нельзя считать доказательством работающего GPU.
