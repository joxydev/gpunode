# Стартовый экран и вход · 2026-09-15

При любом старте показывается приветственный экран. Проверка Telegram initData больше не переключает экран на дашборд. WebApp.expand вызывается при старте и повторно после инициализации; принудительного fullscreen нет. Кнопка «Войти в аккаунт» видна только в неавторизованном браузере. У вошедшего пользователя есть «Мой аккаунт».

Браузер создаёт запрос входа на пять минут, открывает deep link бота, пользователь сверяет код и подтверждает вход кнопкой. Возвращается в исходную вкладку, которая получает свою сессию. Не нужны отдельный домен для Login Widget или новый токен бота. Подтверждение принимается только через webhook с проверенным секретом и только от пользователя, открывшего запрос в приватном чате.

В базе хранятся SHA-256 секрета запроса и HMAC IP, а не открытые секрет и IP. В Telegram передаётся только идентификатор запроса. Секрет получения сессии остаётся в памяти исходной вкладки. Выдача сессии одноразовая под блокировкой строки; срок, отклонение и привязка пользователя проверяются сервером. Лимит — пять запросов на IP за пять минут. Просроченные записи удаляются при создании новых запросов. Сессия сохраняется в sessionStorage вкладки и проверяется сервером при восстановлении; срок существующей сессии — шесть часов. При потере вкладки до подтверждения нужно начать вход заново.

Из заявки удалено поле workload. Клиент отправляет nodeId, profile и idempotencyKey. Сервер самостоятельно записывает, что распределение задач выполняет сервис, и игнорирует присланное клиентом workload. Старые заявки сохранены; новые договоры, платежи и начисления не включаются этим обновлением.

Миграция добавляет только browser_logins. Деплой запускает сборку, последовательные тесты (для VPS с 1 ГБ RAM), HTTP-проверки на изолированном PostgreSQL, затем делает резервную копию и переключает релиз. В конце добавляет callback_query в allowed_updates существующего webhook и проверяет настройку. URL и токен бота сохраняются. GitHub Actions не требуется.

Проверки: TypeScript/Vite production build; unit-тесты криптографии, рынка и браузерного входа; интерфейс в Chromium с подставленными ответами API и Telegram SDK. Реальные HTTP Nest/Prisma проверки выполняются скриптом на VPS до переключения. Telegram-клиент на телефоне проверяет владелец после деплоя.

Документация: https://core.telegram.org/bots/webapps#initializing-mini-apps и https://core.telegram.org/bots/api#callbackquery.
